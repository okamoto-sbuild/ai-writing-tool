# アプリのセキュリティ点検

このアプリは個人用で、DB もログインも持たない。だから点検の重点は「Web アプリの一般的な脆弱性」ではなく、**API キーと入力した文章が、本人の意図しない所へ出ていかないか**にある。具体的には次の経路を潰す：

1. キーがファイル・画面・ログ・同期フォルダ・ソースから漏れる
2. 同じ LAN の他人がこのアプリを開き、本人のキーで生成できてしまう（Streamlit は既定で全インターフェースで待ち受ける）
3. 共用の有料キー（`GEMINI_API_KEY`）や無料枠のキーに、意図せず切り替わる（無料枠では入力が Google の製品改善に使われる）
4. 生成結果に仕込まれた HTML・スクリプトが画面で動く

## 進め方

### 1. 機械的な点検スクリプトを走らせる

```
PYTHONIOENCODING=utf-8 python .claude/skills/app-security-check/scripts/check.py
```

（プロジェクトのルートで実行。PowerShell なら `$env:PYTHONIOENCODING='utf-8'; python ...`）

標準ライブラリだけで動く。キーの値は一切表示せず、長さと「設定あり／なし」だけを出す。出力の各行は `[要対応]` `[注意]` `[OK]` `[情報]` のどれかで始まる。

**`.env` やキーの入った設定ファイルを cat や Read で開かないこと。** 会話に値が残る。中身の確認が必要なら、スクリプトのように値を伏せて調べる。

### 2. コードを読んで、スクリプトでは判断できない点を見る

スクリプトは「設定が無い」「この文字列がある」までしか分からない。次はコードを読んで判断する：

- **プロンプトインジェクション**：メール返信・要約・翻訳などは、他人が書いた文章をそのままプロンプトに入れる。今は `stream_generate` が自動関数呼び出し（AFC）を無効にしており、モデルに道具が無いので、影響は「出力の文章がおかしくなる」までに留まる。AFC を有効にした・tools を渡した・出力を別の処理（ファイル書き込み、コマンド、URL を開く等）に渡すようになった場合は、重大度を上げて報告する。
- **出力の表示**：`st.markdown(output)` は `unsafe_allow_html` が既定 False なので HTML は無効化される。`unsafe_allow_html=True`、`st.html`、`components.html` が増えていたら、生成結果をそこへ流していないか追う。
- **エラー表示**：`st.error(f"...{e}")` に例外の中身がそのまま出る。キーや内部パスが例外メッセージに含まれうる箇所が無いか。
- **キャッシュ**：`get_client`／`get_models` は API キーを引数にしてキャッシュしている。1人で使う前提なら問題ない。複数人で使う形に変えるなら、サーバーのメモリにキーが残ることを指摘する。
- **入力欄でのキー入力**：サイドバーの手入力は `type="password"` であること。
- 前回の点検以降に追加・変更された `Tool` があれば、その `build_prompt` と `system` を一通り見る。

### 3. 報告書を書く

次の形で、重大度の高い順に並べる。各項目は「何が」「なぜ危ないか（このアプリの使い方に即して）」「直し方（具体的なファイルと書き方）」の3点。直し方は提案に留め、**ファイルは書き換えない**。直すかどうかは本人が決める（点検を頼まれただけで設定を変えると、起動方法などが黙って変わってしまうため）。

```markdown
# セキュリティ点検結果（YYYY-MM-DD）

## まとめ
<要対応 N件・注意 N件。いちばん先に手を付けるべきもの1つを1文で>

## 要対応
### 1. <見出し>
- 何が：
- なぜ危ないか：
- 直し方：

## 注意
...

## 問題なし（確認した項目）
- <項目>：<根拠を1行>

## 点検しなかったこと
- <例：pip-audit が無いので既知の脆弱性の照合はしていない>
```

「問題なし」と「点検しなかったこと」も必ず書く。何も書いていないと、見た上で問題なかったのか、見ていないのか区別がつかない。

## 重大度の目安

- **要対応**：今の使い方で実際に漏れる・他人が使える状態。例：待ち受けアドレスが未設定で LAN に公開されている、ソースや `.env.example` にキーの実物がある、XSRF 保護が切られている、生成結果を HTML として表示している。
- **注意**：条件次第で問題になる、または本人が承知の上で置いているもの。例：`.env` が OneDrive で平文同期されている（本人も把握済みの未解決事項）、共用の `GEMINI_API_KEY` にフォールバックしている、依存パッケージのバージョンを固定していない、利用統計の送信が有効。
- **情報**：今は問題ないが、変更時に気をつけること。例：git 管理を始めるなら `.gitignore` に `.env` を入れる。

本人が既に承知して選んだもの（OneDrive 上に置く、venv を使わない、など）は「注意」に留め、理由とともに「承知の上なら現状維持でよい」と書く。プロジェクトの `CLAUDE.md` に書かれた方針を、点検の名目でひっくり返そうとしないこと。

## このアプリ固有の前提（点検の判断に使う）

- キーの探索順は `WRITING_TOOL_API_KEY` → `GEMINI_API_KEY` → `GOOGLE_API_KEY` → サイドバー入力（`gemini_client.API_KEY_VARS`）。`GEMINI_API_KEY` はユーザー環境変数で、別アプリ（有料枠）と共用。**共用の変数を書き換える提案はしない。**
- `.env` は `load_dotenv()` で読むが、既存の環境変数は上書きしない。だから `.env` に `GEMINI_API_KEY` を書いても効かない。
- 起動は `streamlit run app.py` か `起動.bat`。待ち受けアドレスを直すなら `.streamlit/config.toml` の `[server] address = "localhost"` が一番素直（`起動.bat` だけ直すと、コマンドから起動したときに漏れる）。
- 作業フォルダは OneDrive 配下。
